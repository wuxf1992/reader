# 统一主题与旧配色迁移

书架、设置、阅读页使用同一个主题状态和同一个配色选择器。入口是「我的 → 外观与主题」和阅读页「外观 → 主题」。保留原有 21 套自定义配色、5 种纸色，加上暖陶、雾蓝、青绿、黑白灰，共 30 项。

- 日间、夜间、跟随系统共用一个明暗状态；日夜分别记住配色。选择固定配色时自动切到对应明暗；阅读页日夜按钮也修改全局状态。
- 跟随系统时可分别选择日间和夜间配色，系统切换后所有页面一起更新。固定夜间配色不能放入日间槽位，反之亦然。
- 唯一存储为 `reader.appearance.v1:<服务器和账号作用域>`。先读取旧 `reader.theme.v2` / V3 偏好，再一次性导入实际生效的设备阅读配色、日夜记忆。迁移后旧 `AppSettings.readingTheme/paper/theme` 不再覆盖新选择；旧字段保留读取兼容，旧存储不删除。
- 字号、亮度、行距、页边距、繁简、液态玻璃和阅读位置保持原值；羊皮纸与牛皮纸纹理保留。主题存储失败会报告错误，不能阻止缓存开书。
- 状态解析、令牌应用和选择器位于 `web/src/shared/theme/`；阅读页订阅同一状态。换颜色只更新语义令牌和浏览器取色，不调用正文 `applySettings`，避免无关的分页、动画和位置恢复。
- 阅读外观的字号、行距、亮度在主题目录之前，主题目录默认折叠；保留用户已保存的展开状态。

## 合并主线时的验收约束

1. 将上游配色能力合入现有共享模块；不要重新引入独立阅读主题或纸色覆盖层。
2. 单元与集成检查覆盖旧配置迁移、重复迁移、异常存储、服务器/账号隔离、系统切换，以及颜色切换不重新分页、不移动位置。
3. `web/tools/ui-review/reader-unified-themes.mjs` 使用生产包，在 Chromium/WebKit、390×844 和 1440×768 下检查 120 次选择、根页面/正文/弹窗颜色一致、两个入口往返、刷新恢复、系统日夜配对和首屏字号可见。
4. 主题变更影响全局页面，必须检查整站布局与离线启动。系统栏检查使用 `reader-status-tint.mjs`，不能以手机适配替代桌面任务验证。

iPhone 原生 Safari 系统栏、键盘和系统合成层仍需真实设备检查；WebKit 模拟不等同于真机。

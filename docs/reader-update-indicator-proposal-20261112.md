# Reader 新章节标识：调研与建议（2026-11-12）

目标：回到书架就能看出哪些连载有新章节，开书自动取得已检查的新目录，继续当前阅读。

已确认的现状：服务端 ChapterUpdates 按订阅定时检查并比较稳定 href；new_chapters 是检测新增后的累计值，当前只有配置接口支持 acknowledge，网页没有调用；书架没有显示该状态。不能把这个累计值直接标成“未读 N 章”。

建议的交互：
- 连载封面右上显示带文字的“新章节”；有准确待读新增数时用“新 3 章”，零时隐藏。沿用现有书架样式，格式标签和阅读进度保留，不靠颜色独自表达含义。
- 标识表示仍有新章节待读。打开旧章节、加载目录或预缓存不清除；读到新增部分后的消除时机以用户选择为准。默认建议读完新增部分再清除，而非开书即清除。
- 开书先显示本机可读正文，在后台采用 Reader 已检查的新目录；目录、章数和后续导航同时更新，当前正文、选择和位置不重建。
- 回书架、应用回前台和联网恢复时刷新 Reader 的状态查询。书架长时间可见时低频查询 Reader，后台暂停；外部书站仍由现有服务端订阅任务按间隔检查。

实现边界：复用现有订阅 worker、阅读进度和查询缓存。服务端将检测到的新增章节与该账号的阅读位置关联，区分“检测新增数”和“尚未读到的新章节”。确认带观察版本，不能用无条件清零吞掉并发新更新。用稳定章节 href 对比，目录重排、章节删除、改标题、正文修订及换源不因总数或更新时间变化误报。刷新失败保留已知提醒；离线保留上次确认状态，不声称刚检查成功。账号/服务切换不得沿用其他用户的标识。

先修复已确认的目录缓存衔接 bug；本文件是标识方案，角标尚未实现。

# 主题一致性与桌面体验评估（2026-10-29）

## 结论与范围

建议全站统一为“跟随系统 / 日间 / 夜间”，阅读快捷按钮编辑同一模式。阅读纸张、字号、行距是阅读偏好，保留旧配色并迁移到统一模式下的纸张选择，不再形成另一套独立日夜状态。

本轮是评估，没有修改运行代码或部署。源码基线为 `88e903d`，运行前端为 `custom-release-optimized-20261029`。使用同一 fixture 数据与书籍，Chromium 对比 390×844、1440×1000、1920×1000；补查当前 1440×768 笔记本高度，并对比归档 10 月 17 日桌面阅读页面。所有测试账号与数据均在本地 fixture，未访问正式账号。

## 桌面回退应如何判断

本轮对比的当前版本、上次完整主线发布前的 `28e6d4e`，以及 10 月 17 日归档，桌面主体几何基本一致：1440 宽下正文容器 832px、工具栏 800×72px。不能据此认定最近一次缓存/首屏优化单独造成桌面布局退步，也不能凭这些样本证明用户更早喜欢的版本是什么。

当前默认场景未复现按钮越出视口或整页横向溢出。已观察到的桌面问题是设置层级与信息密度：常用字号被大量主题挤出首屏，外观抽屉接近满高；阅读控制栏显现时还覆盖正文上下区域。最后一项部分源于现有“不因工具栏显隐而重排正文”的约定，需要单独定义桌面布局策略，不能用一次全局 CSS 修改同时改变手机分页和桌面控制栏。

正文限制合理行长应保留；桌面改善应针对常用任务、控制栏位置和设置组织，不以把正文铺满整个屏幕作为验收目标。[web.dev 响应式设计指南](https://web.dev/articles/responsive-web-design-basics)也强调按内容与输入能力调整布局，而不仅是按设备缩放。

## 推荐的收敛方案

1. **一套模式**：全站只保留一个 `system / light / dark` 决策，界面名为“跟随系统 / 日间 / 夜间”。全局设置和阅读快捷入口编辑同一来源；手动选择明确覆盖系统，重新选择跟随系统后恢复自动变化。[prefers-color-scheme 文档](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-color-scheme)说明了系统/浏览器偏好的检测机制。
2. **纸张是二级偏好**：配色、纸纹继续保留，日间和夜间各有合适纸张；旧配色和用户选择迁移保留。顶层优先显示模式、字号、行距，完整纸张目录进入二级选择，避免 28 项抢占首屏。
3. **唯一状态与规则**：复用现有 shared/theme 作为外观来源。全局与阅读入口都读取实际生效值；旧 theme/paper/readingTheme 字段只在迁移边界处理，随后停止双向回写。设备排版设置仍负责字号/行距，缓存和进度保持各自职责。
4. **颜色与排版分开**：颜色更新只更新语义令牌及系统栏，不触发分页重算；字号、行距、宽度变动才走排版路径。继续保留 iPhone 真实可见颜色采样，避免主题改造破坏系统栏。
5. **共享行为、分别布局**：手机保留现有沉浸和触摸翻页；桌面优先保证常用阅读操作与字号调整，目录/设置按可用空间组织，避免遮挡正在操作的正文。CSS 按组件与明确断点负责布局，减少 reader.css 与 app/shell.css 对同一控件反复覆盖。

## 实施次序与发布门槛

- 第一批修真实失效：两个主题入口读取/写入同一生效状态，处理旧纸色控件；先把字号/行距放回桌面设置首屏。
- 第二批统一全局模式与旧配置迁移；保留阅读纸张与用户历史偏好，删除重复入口和优先级分支。
- 第三批按桌面任务整理布局，并分离颜色与排版更新；移动端使用现有对照基线验证。
- 收敛期间优先处理已有任务回退，暂缓新的主题、视觉效果与阅读工具扩展。

每一批验收真实用户路径：

1. 全局选夜间 → 打开阅读 → 返回书架 → 刷新：全站模式一致，选择状态与画面一致。
2. 阅读快捷切换 → 回全局设置：显示同一个实际选择；跟随系统时系统变化能到达全部界面。
3. 纸张选择即时生效、重开保留，旧设置迁移不清空用户配色。
4. 1440×768 外观首屏能直接调整字号/行距；手机 390、窄桌面/平板 768、常用桌面 1280/1440 和宽桌面 1920 都能完成阅读任务。
5. 只切日夜不重算分页、不改变章节/文本位置；已有缓存优先、断网恢复、连续翻页、目录、搜索、朗读和账号隔离继续通过。

此前测试覆盖了局部控件、无溢出与阅读/应用隔离，却没有覆盖“从两个入口编辑同一种外观应得到相同结果”。新的验收应以这些跨入口任务为准；测试数量与截图数量仅作为证据索引，不是体验质量结论。

# 操作反馈和滚动条调研

2026-10-08。只读核对当前源码和已部署 CSS，未修改线上功能。

此文记录实施前的调研；后续已完成的修改与验证见 [UI-FEEDBACK.md](./UI-FEEDBACK.md)。

用户需求：点击后立即确认操作已接收；若 100ms 后仍未完成，显示局部加载提示或动画。100ms 是提示延迟，不是网络请求超时，也不能为了动画延迟显示已返回的内容。

## 已确认的缺口

| 位置 | 当前行为 | 建议 |
| --- | --- | --- |
| 首次打开网页 | index.html 的启动层只有静态图标；JS 启动后才移除 | HTML 自带轻量启动反馈，100ms 后显示动画和文字，避免依赖尚未加载的 JS |
| 搜书 | sources-screen.tsx 在请求前已设 searching 并重绘，但只有进度文字；搜索按钮禁用后仍是原图标 | 搜索按钮及结果区域超过 100ms 显示转圈；已有结果保持可读，继续显示来源进度和停止按钮 |
| 普通按钮 | toolkit.tsx 的 Button、IconButton 没有 busy 属性；部分页面已有全局转圈提示 | 复用现有图标和颜色，点击按压即时反馈，异步按钮接入 100ms busy；文案、按钮宽度和焦点保持稳定 |
| 目录跳转 | reader-screen.tsx 的跨窗口路径有全局加载提示，本地窗口路径没有统一加载状态；目录行没有正在跳转标识 | 目标章节行显示选中及局部加载，内容准备好后再完成切换；覆盖小说与本地书的跳转路径 |
| 插件管理 | plugin-page-screen.tsx 已有 aria-busy 和全局「正在处理」动画，但提交按钮只有禁用 | 保留现有错误和成功提示，补提交按钮对应的 busy，避免每次短请求都闪一次全局提示 |
| 书架、列表、媒体库 | 已有骨架屏、部分 spinner，触发规则各不相同 | 复用现有加载布局，统一显示延迟；后台预取、进度同步不弹全局 loading |

现有 notifications.ts、FloatingNotice、MediaLoading 和 spinner 样式已能提供转圈或骨架屏，不需要新增动画库。已有按压反馈集中在部分图标按钮、工具栏和书卡，不是所有操作统一拥有。

## 时序与清理

1. 操作开始立即更新 busy 语义、按压/选中反馈和防重复状态。
2. 100ms 内完成则取消计时，不显示加载动画。
3. 超过 100ms，在按钮或对应区域显示带文案的 loading。
4. 成功即显示内容；失败改为错误和重试；取消、返回、切换页面或被新操作替代时，取消计时并清除旧提示。

不能把后台轮询、预取等所有 HTTP 请求都绑定到全屏遮罩。页面打开、用户搜索、章节跳转和用户提交才属于本次交互反馈范围。保留搜索过程中查看详情、加入书架和停止搜索的现有能力。

100ms 计时不能解决同步重排或大量目录渲染阻塞主线程的问题。应验证提示是否真正绘制；若重操作阻塞首帧，先让浏览器绘制反馈，再做重操作。网页 HTML 尚未到达浏览器时，应用自己的启动提示也无法显示。

## 滚动条

源码与已部署 CSS 都缺少页面、书架、目录、弹窗等滚动区域统一的主题滚动条颜色。仅媒体选择菜单设置 scrollbar-color，阅读侧栏单独设置 WebKit thumb。当前看到的黑色与浏览器默认绘制相符，尚未在用户设备上取到计算样式。

建议使用现有主题色：浅色灰褐、护眼色棕色、深色浅灰，轨道透明或使用对应面板背景；同时设置匹配的 color-scheme。使用标准 scrollbar-color/scrollbar-width，按浏览器支持提供 WebKit 回退；支持标准颜色时不要让回退覆盖标准行为。保持歌词、分页正文等原本隐藏滚动条的区域不变，不改变滚动和分页布局。

参考：[MDN scrollbar-color](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/scrollbar-color)、[MDN scrollbar-width](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/scrollbar-width)。标准颜色会继承，根元素设置也会影响视口；颜色对比和旧浏览器回退需要实际验证。

## 最小实施范围和验证

先统一 Button/IconButton、现有通知组件的 busy 时序，再接搜书、目录跳转、插件提交和页面初次加载；最后在公共样式与媒体主题中补滚动条颜色。调用方、取消/销毁路径、现有 skeleton 和 startup HTML 需要一起检查。

模拟 50ms、150ms 和长请求，检查短请求不闪、慢请求有提示、结束即清理、失败可重试、页面切换不遗留提示、旧请求不覆盖新请求；检查搜索可停止、目录跳转不改变位置恢复。浏览器检查浅色/护眼/深色主题、桌面与手机、键盘焦点，以及 reduced-motion 下的静态提示。iPhone 原生覆盖式滚动条是否接受指定颜色需真机确认。
